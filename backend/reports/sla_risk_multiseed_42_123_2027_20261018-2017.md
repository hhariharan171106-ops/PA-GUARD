# Multi-seed SLA-breach evaluation (synthetic data)

Every result below is a synthetic-data evaluation against the stated simulator, not real-world healthcare performance.

- Samples per independent run: 6000
- Seeds: 42, 123, 2027
- Split per run: stratified 60% train / 20% validation / 20% test.
- Thresholds are selected from each run's validation split only.

## Leakage and target definition

sla_breach = 1 when simulated future resolution hours exceed positive hours remaining at prediction time; otherwise 0.

At generation time, synthetic payer, service, status, unresolved document count, workflow failure count, and pending task count contribute to a typical simulated resolution duration. Stochastic log-normal noise is applied. A breach label is 1 when that hidden duration exceeds positive `hours_remaining`; otherwise it is 0. The hidden duration and label are not model features.

Rows are independently sampled; exact repeated feature rows are counted in each per-seed report. Train, validation, and test partitions are disjoint; preprocessing/model fitting uses train only, threshold selection uses validation only, and the test set is used for reporting only. Shared simulator rules across splits are intentional and mean this does not test temporal or distribution-shift generalization.

## Conclusion and limitations

Seed-to-seed stability here supports only more offline testing against this simulator. It does not establish deployment readiness. Real-world assessment requires time-stamped, representative and appropriately de-identified historical cases, verified SLA breach outcomes, temporal and payer/service-group holdouts, calibration, error/subgroup analysis, operational threshold review, and prospective shadow-mode evaluation. The model must not make clinical, authorization, or payer-submission decisions.
